PROJECT REQUIREMENTS
--------------------------------------------------------------------------------

What to Create: Build or significantly update working applications using Amazon
developer tools in the following primary tracks (each a "Project").

PRIMARY TRACKS:

- Fire TV: Launch a demo-ready app that works on Fire OS or Vega OS. Priority
  categories: AI-enhanced viewing, sports, fitness, family entertainment,
  multi-modal UX, and computer vision.

- Alexa+: Build a working Agent Skill or a self-hosted MCP server, implementing
  MCP spec version (minimum acceptable version is 2025-11-25). Optionally,
  developers can simulate the Alexa+ experience in a web app using their own
  agentic tools.

- Bee (Wearable AI): Build a project that connects to data recorded and
  processed through a Bee device or Apple Watch running Bee software, using
  Bee's CLI, MCP, or Agent Skills. The demo must show the project using that
  data to deliver value to a user. Priority use cases: education, developer
  experience, and personal productivity.

- Ring: A working app or new feature that utilizes Ring APIs, SDKs, simulators,
  or devices, demonstrated through a simulator or an actual device. Priority
  categories: access control, business systems, IoT home automation,
  accessibility, and caretaking.

MINI CHALLENGES:

- AWS Builder (Mini Challenge): Any primary track project that incorporates AWS
  services (e.g. Amazon Bedrock, AgentCore, Strands SDK, Kiro Crew, SageMaker)
  with documented integrations. Kiro Crew qualifies on its own as a development
  tool used during the hackathon — a submission does not need to also call a
  runtime AWS service to count for this mini-challenge.

- Open Source (Mini Challenge): Create a new open-source project or contribute
  to an existing public repository during the hackathon window, alongside a
  primary track submission. Contributions can be a new repo (with open-source
  license), a branch, a fork, or a pull request. PRs do not need to be merged;
  share your forked version if unmerged. Required: contribution URL, project
  repository URL, GitHub username, and a description of what you did, how it
  works, and why it matters.

Functionality: The Project's code repository must include clear setup and run
instructions, and the Project must be shown functioning in the demonstration
video, as depicted in the video, URL and/or expressed in the text description.

Platforms: The demonstration video must show the Project functioning on the
platform for which it is intended and which is specified in the Submission
Requirements.

New & Existing: Projects must be newly created, or if pre-existing, must have
been significantly updated after the start of the Submission Period. Entrants
must explain and demo how their Project was significantly updated.

Third Party Integrations: If a Project integrates any third-party SDK, APIs
and/or data, the Entrant must be authorized to use them per their terms and
licensing.

SUBMISSION REQUIREMENTS
--------------------------------------------------------------------------------

Submissions must:
- Include a Project built with the required developer tools that meets the
  Project Requirements.
- Include a text description explaining features and functionality.
- Provide a URL to a public GitHub code repository for judging and testing. The
  repository must contain all necessary source code, assets, and instructions
  required to be functional. It must be public and open source with an open
  source license file, detectable and visible at the top of the repository page
  (in the About section).

For Alexa+, Bee, and Ring: The repository must demonstrate use of your track's
required technology at runtime in your code — imported and actually called (a
library import, an app/backend entry point, or a loaded agent/flow/MCP config),
not just named in the README. Fire TV is the exception (see below).

- Fire TV: Any framework or language is acceptable (React Native, Android/
  Kotlin/Java, web technologies, etc.). The requirement is that the project runs
  on Fire OS or Vega OS. The demo video must show the project running on an
  actual Fire TV device or the Fire TV/Vega simulator.

- Alexa+: A working Agent Skill or a self-hosted MCP server, implementing MCP
  spec version 2025-11-25 (or later, once confirmed) over Streamable HTTP.
  Alternatively, entrants may submit a simulated Alexa+ experience — built with
  any AI or agentic tool of their choice, no specific framework/SDK/MCP surface
  required. This alternate path is exempt from the runtime-technology-hook
  requirement above; the repository must still include the simulation's source
  code, and the demo video must clearly show the simulated experience.

- Bee (Wearable AI): The project must be connected to data recorded and
  processed through an actual Bee device or an Apple Watch running the Bee
  software. The demo video and code must show the project actually using that
  Bee data to do something for a customer; mentioning Bee without a live data
  interaction does not count. No public-facing integration is required.

- Ring: Any Ring API, SDK, simulator, or device listed in Ring's developer
  documentation is acceptable. The demo video must show the project working
  through a simulator or an actual Ring device you have for testing.

Include a demonstration video of your Project. The video:
- Should be less than three (3) minutes (judges need not watch beyond three
  minutes).
- Should include footage showing the Project functioning on the device it was
  built for.
- Must be uploaded and made publicly visible on YouTube or Vimeo, with a link
  provided on the submission form.
- Must not include third party trademarks, or copyrighted music/material unless
  the Entrant has permission.

Include Product Feedback for each tool, API, or SDK used:
- Which developer tools, APIs, and SDKs did you use and for what?
- What worked well? (setup, documentation, docs, testing, performance,
  reliability)
- What needs work? (system errors, docs sections, missing features,
  compatibility issues, tool limitations, required workarounds)
- How was your onboarding experience (getting from zero to hello world)?
- Would you build with these devices and services again? Yes/No and why.

- Identify which Primary Track(s) you are submitting into.
- Identify which Mini Challenge(s) you are participating in.
  - AWS Builder (Mini Challenge): Describe which AWS service(s) you used and how,
    in your Product Feedback answer.
  - Open Source (Mini Challenge): Provide contribution URL, project repository
    URL, GitHub username, and a description of what you did, how it works, and
    why it matters.

Optional - Feature Requests: description, why it matters to your project, and
priority rating (Critical / Important / Nice-to-have).

Optional - Friction Log Entries: specific task attempted, steps taken, expected
vs. actual result, severity rating, workaround used, and actionable suggestion.
Participants who submit friction logs score higher in judging (up to 10% bonus).

Multiple Submissions: An Entrant may submit more than one Submission, but each
must be unique and substantially different (at Sponsor/Devpost's sole
discretion).

Submission ownership: Be the original work of the Entrant, solely owned by the
Entrant, and not violate the IP rights of any other person or entity.

Testing: The project must be accessible to judges (via code repository and demo
video). Projects need not be publicly available to all participants. If the
Entrant's website is private, include login credentials in the testing
instructions. The Project must be available free of charge and without
restriction for testing, evaluation, and use by the Sponsor, Administrator, and
Judges until the Judging Period ends. Judges may judge based solely on the text
description, images, and video. For software running on proprietary/third-party
hardware not widely available to the public, the Sponsor/Administrator may
require physical access to the Project hardware.

Language Requirements: All Submission materials must be in English, or the
Entrant must provide an English translation of all materials.

Team Representation: A Team or Organization must appoint one authorized
Representative (meeting eligibility requirements) to enter the Submission.

Intellectual Property: The Submission must (a) be the Entrant's original work;
(b) be solely owned by the Entrant with no other person/entity having rights;
and (c) not violate any IP or other rights. Open source software/hardware may be
used if the Entrant complies with applicable licenses and creates software that
enhances and builds upon the underlying open source product.

Financial or Preferential Support: A Project must not have been developed with
financial or preferential support from the Sponsor or Administrator (funding,
investment, contract, or commercial license prior to the end of the Submission
Period). The Sponsor may disqualify a Project if awarding a prize would create a
real or apparent conflict of interest.

6. JUDGES & CRITERIA
================================================================================

Sponsor and Administrator determine eligibility and judging methodologies
(expert panels, peer review, automated AI-driven analysis, or a combination).

Stage One: Pass/fail on baseline viability — the Project reasonably fits the
theme and reasonably applies the required APIs/SDKs.

Stage Two: Submissions that pass Stage One are evaluated on the following
equally weighted criteria, at the judges' sole and absolute discretion:

- Tech Implementation: How well is the project built, and how effectively does
  it use the required tech (APIs, SDKs, or device capabilities for the track/
  mini-challenge)?
- Design: Does the project deliver a complete, coherent product experience? Is
  the interaction model intuitive for the target device or platform?
- Potential Impact: Does the project make a credible, specific case for solving
  customer needs? Could it realistically serve an audience beyond the hackathon
  (e.g. Fire TV Appstore, Ring Appstore)?
- Quality of the Idea: Is this a creative, imaginative use of the required
  tools? Does the team understand the developer ecosystem and end-user needs?
  Judges distinguish creative ideas from obvious ones (examples per track
  provided in the official rules).

Bonus Points: During Stage 1 downselection, Amazon's internal review team
assesses each submission's friction log entries (if provided) and passes a
recommended bonus — up to 10% — to the Stage 2 judging panel, which applies it
to the submission's final spreadsheet score.

Tie Breaking: For each Prize, ties are broken by the highest score in the first
applicable criterion, repeated as needed; if still tied, the panel of Judges
votes.
